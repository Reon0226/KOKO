# KOKO — きみの字で、話そう。

自分の字のまま届く、1対1のメッセージアプリ（Web MVP）。
同梱の試作（`prototype/index.html`）を土台に、**実際に二つの端末の間で手書きが届く**ところまで作りました。

- 外部ライブラリなし。Node.js 22.5 以上の標準機能（http / crypto / node:sqlite）だけで動きます。
- 画面は素の HTML / CSS / JavaScript（ES Modules）。ビルド不要。PWA としてホーム画面に追加できます。

## 起動

```bash
cd KOKO
npm start                 # http://127.0.0.1:8787 を開く
```

データは `data/koko.db`（SQLite）に保存されます。場所は `KOKO_DB=/path/to/koko.db` で変えられます。

### スマホ2台で試す

```bash
HOST=0.0.0.0 PORT=8787 npm start
```

同じ Wi‑Fi のスマホで `http://<PCのIPアドレス>:8787` を開きます。
1台目で名前を入れる →「＋ 友達を招待する」→ リンクを2台目に送る（LINE やメールなど、あなたの手で）→ 2台目で開いて名前を入れると、ふたりのトークができます。

HTTP のままだと、Service Worker（オフラインで開く）・コピー・共有ボタンなど一部のブラウザ機能が使えず、通信も暗号化されません。実際に人に使ってもらうときは HTTPS で公開してください。

```bash
TLS_KEY=key.pem TLS_CERT=cert.pem HOST=0.0.0.0 npm start   # HTTPS で起動（Cookie に Secure、HSTS も付きます）
# リバースプロキシ（nginx 等）で HTTPS を終端する場合は COOKIE_SECURE=1 npm start
```

SSE（リアルタイム受信）を通すため、プロキシではレスポンスのバッファリングを切ってください（`X-Accel-Buffering: no` は送っています）。

## テスト

```bash
npm test          # サーバー API（認証・招待・権限・検証・重複排除・SSE再送）＋お手本候補のテスト
npm run e2e       # 二端末 E2E（Playwright の Chromium。node tests/e2e.cjs <保存先> でスクリーンショットも）
npm run metrics   # 普及検証の集計（筆跡や本文は読まない）
npm run icons     # アイコン SVG / PNG の再生成（Python fontTools と Playwright が必要）
```

## 使い方（画面）

| 操作 | 内容 |
|---|---|
| マスに書く | 1マス1文字。光っているマス（次のマス）に書き始めると、その字に移ります。画の途中で勝手に確定・移動しません |
| ‹ › | 前／次の字へ。下書きの字をタップしてもその字に移れます |
| ↶ 戻す | 直前の操作を1つ取り消す（1画・削除・空白・改行）。他の字は壊しません |
| ⌫ 削除 | 今の字を消す（空きマスなら一つ前の字）。消した直後に「↶ 戻す」も出ます |
| 空白 ／ 改行 | 別のマス（token）として入ります |
| ⤢ 大きく | 1マスだけを大きく表示（画数の多い漢字用） |
| 候補（またね、気持ち…） | **お手本**。押すとマスの背景に薄く出ます。本文には何も入りません |
| 🔍 | お手本を読みで探す（例：きもち → 気持ち） |
| 見本 ON/OFF | お手本の表示を切り替え |
| ＋ 読み上げ用テキスト | 任意。スクリーンリーダー用に筆跡と別に届きます（筆跡の代わりにはなりません） |
| 会話をタップ | マスをしまう（キーボードを閉じる感覚）。「✎ マスを出して書く」で戻ります |

設定：マスの数（2/3/4）、左手向き（送るボタンを左に）、お手本の見せ方（マスに薄く／上に出すだけ）、読み取り補助、通知、引き継ぎコード、ログアウト、全端末ログアウト、アカウント削除。

## 構成

```
server/server.js      API・SSE・静的配信（認証、招待、1対1、配信状態、ブロック、通報、削除）
server/validate.js    送信 payload の検証（未知の項目を拒否＝お手本・認識文字は入れられない）
server/db.js          SQLite スキーマ
public/index.html     画面
public/js/composer.js 手書きマス（入力・お手本・undo）
public/js/ink.js      筆跡の記録と描画（補正なし）
public/js/app.js      画面遷移、送信待ちの列、再接続、配信状態、設定
public/js/api.js      通信（失敗の種類を区別）と SSE の再接続
public/js/guides.js   お手本の辞書と候補
public/js/recognizer.js 手書き認識（読み取り補助）のアダプター
public/js/store.js    端末内保存（下書き・送信待ち・設定。ログアウトで消去）
public/sw.js          画面だけをキャッシュ（会話は入れない）
public/icons/         アイコン（SVG・PNG・マスカブル）
prototype/            同梱の元の試作（比較用にそのまま保存）
docs/DESIGN.md        設計メモ（データ・安全・認識・ネイティブ化・検証計画・確認したいこと）
```

## 送信メッセージの形

```json
{
  "id": "m_…", "conversationId": "c_…", "senderId": "u_…", "clientMessageId": "…",
  "serverTimestamp": 1793500000000, "payloadVersion": 1, "seq": 12,
  "tokens": [
    { "kind": "ink", "strokes": [[{ "x": 0.21, "y": 0.30, "t": 0 }, { "x": 0.79, "y": 0.31, "t": 96 }]] },
    { "kind": "space" },
    { "kind": "newline" }
  ],
  "altText": null, "deliveredAt": null
}
```

`x, y` はマス内の 0〜1、`t` は画の書き始めからのミリ秒、`p` はペンの筆圧（ある場合のみ）。

## 検証結果（2026-11-01、この環境で実行）

- `npm test` … 6件すべて成功
- `npm run e2e` … 27件すべて成功（iPhone 13 / Pixel 7 相当の画面、別々の Cookie・保存領域を持つ3つのブラウザ）

E2E で確かめたこと：招待リンク作成と1回限りの受け入れ／タッチで書いてもスクロールしない／1マス1文字・画順どおりの記録／マス移動後も線が残る／お手本を選んでも下書きが変わらない／お手本が空白・改行マスを飛ばして続く／空白・改行が別 token／↶ が直前の1画だけを戻す／⌫ と ↶ で元に戻せる／送信 payload にお手本・認識文字が入らない／相手に同じ順序・空白・改行・座標で届く／「届きました」の表示／オフライン送信→「未送信」→再接続で自動送信→二重にならない（同じ clientMessageId の再送も同一扱い）／再読み込みしても下書きが残る／マスの数・左手向き／ログアウトで端末内データが消える／マスをしまう・出す／オフラインで開き直して書いて送信待ちにし、つながると届く／ページエラーなし。

## まだ無いもの（正直な一覧）

- **手書き認識は日本語では実質まだ動きません。** Web の Handwriting Recognition API を機能検出して使う作りですが、公式資料では Chromium のみ・ChromeOS は英語のみで、日本語対応の記載はありません。使えない端末では設定に「使えません」と表示し、候補は端末内の小さな辞書（約120語）と読み検索です。文脈に応じた予測変換エンジンもまだありません。
- プッシュ通知（アプリを閉じているとき）。今は開いている間の通知だけ。
- 電話番号・メール・Apple/Google でのログイン。今は「端末のセッション＋引き継ぎコード」だけ。
- E2EE（エンドツーエンド暗号化）。対応していません。画面にもそう書いています。
- 既読、グループ、画像、通話、活字入力（いずれも未決定のため入れていません）。
- メッセージ単位の取り消し・削除、トークの削除、通報の管理画面（通報はサーバーのログと DB に記録）。
- ネイティブアプリ（iOS/Android）。方針は `docs/DESIGN.md`。
- 1サーバー構成（SSE の接続をメモリで持つため、複数台に増やすには Redis 等の配信が必要）。
